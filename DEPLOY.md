# Nazam LLC — Hostinger Deploy Notes

**This file lives at the repo root on purpose. Do NOT put it inside
`hostinger-site/` — anything in that folder is uploaded and served publicly.
It was previously readable at https://nazamllc.com/UPLOAD-INSTRUCTIONS.txt**

*** IMPORTANT: THE SITE IS NOW BUILT FROM SOURCE ***

Files in hostinger-site/*.html are GENERATED. Editing them directly will work
until the next build, then your changes are silently overwritten.

Edit site-src/ instead:
  site-src/partials/head.html     <head> and opening markup (all pages)
  site-src/partials/header.html   topbar, nav, mobile menu (all pages)
  site-src/partials/footer.html   footer (all pages)
  site-src/pages/*.html           one file per page: front matter + body
  site-src/schema/*.html          JSON-LD fragments

0. Build and check before uploading, from the repo root (nazam-llc/):
     npm run build:site
     npm run validate:site
   Do not upload if validate:site reports problems.

1. Log in to Hostinger hPanel.
2. Open File Manager for nazamllc.com.
3. Open the public_html folder.
4. Upload the contents of hostinger-site/ into public_html:
   - index.html
     (do NOT upload this file, DEPLOY.md, or AGENTS.md)
   - ai-automations.html, amazon-walmart.html,
     app-development.html, financial-intelligence.html
   - work.html
   - work/  (folder: chromyne.html, chromyne-salons.html)
   - privacy.html, terms.html, 404.html
   - downloads/  (folder: 2 free resources)
   - styles.css, script.js
   - robots.txt, sitemap.xml, llms.txt
   - .htaccess   (HIDDEN FILE — you must enable "show hidden files" in
     Hostinger File Manager, and Cmd+Shift+. in macOS Finder, or it will
     silently not upload and you will get Hostinger's stock 404 instead)
   - images/  (entire folder, including images/chromyne/ and images/chromyne-salons/)
5. Make sure index.html is directly inside public_html, not nested in a folder.
6. Visit https://nazamllc.com/ and test:
   - Mobile: the hamburger menu opens, all 8 links work, Escape closes it,
     and the "Book a Free Call" button is visible in the header
   - The four capability cards on the homepage are clickable and land on
     the matching service page
   - Work page: both product cards open their case studies; the three
     client outcome cards are deliberately NOT links
   - Footer: the email address is visible at every screen width
   - Both Free Resources links open the guides
   - A made-up URL (e.g. /nope) shows the branded 404 page, not Hostinger's
   - FAQ accordions open and close
   - No sideways scrolling on a phone

Notes:
- Static site. No Node, React, Vite, or database is needed on the server.
- No contact form; all contact CTAs are mailto: links to admin@nazamllc.com.
- Cache busting is automatic. scripts/build.js holds ASSET_VERSION; bump it
  whenever styles.css or script.js changes, and every page picks it up.
- .htaccess sets the 404 page plus X-Content-Type-Options and Referrer-Policy.
  It deliberately does NOT set HSTS: https://www.nazamllc.com currently fails
  its TLS handshake and serves a Hostinger parking page over plain HTTP.
  Fix the www DNS and certificate first, then consider adding HSTS.
- Known outstanding items (not addressed by this release): no analytics
  installed, no contact form, images are still JPEG rather than WebP, and the
  www hostname is broken.
- If the design looks stale after upload, clear the Hostinger/LiteSpeed cache
  and retest in a private window.

## Hand-maintained files (NOT generated by build:site)

`npm run build:site` only reads `site-src/pages/**/*.html`. It never deletes anything
from `hostinger-site/`, so the files below survive builds — but they also will NOT be
recreated if `hostinger-site/` is ever wiped. Keep them in git.

- `oauth/tiktok/callback/index.html` — OAuth redirect target registered with the TikTok
  Business API (both the account-holder and advertiser redirect URLs). Standalone by
  design: no header/footer/analytics, self-contained CSS+JS, `noindex,nofollow`, and it
  transmits nothing — it only reads `auth_code` / `code` out of the address bar and
  displays it. Routed by an `.htaccess` rewrite so the extension-less URL is served
  without a 301. Deliberately absent from `sitemap.xml`.
  Deploy it by uploading the `oauth/` folder alongside the rest of `hostinger-site/`.

  Not added to `robots.txt`: a `Disallow` there would stop crawlers reading the
  `noindex` on the page, which is the weaker outcome. Nothing links to it, so the
  meta tag is the right control.
